## 这个版本做了什么

把 Magic Resume 重做成原生微信小程序，并补上一整套「投简历」需要的工具。

### 编辑与排版

- 隐私脱敏：手机号、邮箱打码后再导出
- 防泄漏水印：自定义文字平铺

### 智能分析（两条路）
- **本地引擎**：不需要联网、不需要 Key
  - JD 匹配雷达：中文 n-gram + 英文词元 + 词库三路抽取
  - ATS 体检：14 项加权检查
  - 面试官模拟：从经历里找触发点生成定向追问
  - STAR 改写：弱动词升级、去第一人称、补方法链路
  - 时间线体检：倒序、空档、时间冲突
- **接入大模型**：填自己的 Key，支持 DeepSeek / OpenAI / 通义 / 豆包 / Kimi 与任意 OpenAI 兼容服务
  - 5 个预设任务，SSE 流式输出

### 投递闭环
- 多版本简历，任意一版可单独预览
- 投递漏斗：已投递 → 被查看 → 面试 → Offer
- 电子名片 + 30 秒语音自我介绍
- 8 枚成长徽章

### 质量
- 59 项离线测试，mock 掉 wx / wx.request / Canvas
- 全部 JS 通过语法检查，WXML 标签闭合校验

### 已知限制
- 需要微信开发者工具导入，无在线体验
- 导出是长图不是 PDF
- 接入大模型需自行配置 request 合法域名

### 许可
衍生自 Magic Resume（Apache 2.0 + 附加非商用条款），仅限个人非商业使用。

## 八、技术向（V2EX / 掘金 / 少数派）

**标题**

```
用原生小程序重做一个简历编辑器：零依赖、离线 AI、59 项测试
```

**正文**

```markdown
## 起因

Magic Resume 是个不错的 Web 简历编辑器，但它是 React + TanStack Start，
要部署、要开浏览器。我想验证一个假设：**简历编辑器的复杂度到底有多少？能不能用原生小程序从零实现？**

结论是能。8 个页面、5 个 utils、零依赖、没有构建步骤。

## 三个值得说的技术点

### 1. 本地跑「AI」

没有云函数、没有后端。关键词抽取是三路融合：

- 词库命中（权重 3.0）
- 中文 n-gram 频率（1.4）
- 英文词元（1.6）

中文分词没有库，就用滑动窗口取 2 到 6 字的 n-gram 统计频次，再用三层过滤去噪：
首尾虚词黑名单、内部停用二元组、被更长词包含时丢弃。

调这个抽取器花的时间比写页面还多。中途踩过一个坑：我一度把「独 / 内 / 人 / 位」
当成停用字，结果「独立站」「内容管理」「用户」全被误杀，匹配度直接归零。

效果对比（同一段建站岗 JD）：
- 旧版：51 个词，大半是「成客户网站交」这种碎片，匹配度 0
- 新版：23 个干净词，匹配度 18%（低分是对的，简历确实是前端背景）

### 2. SSE 流式在真机上的两个坑

接大模型时用 `enableChunked: true` 做流式，结果真机上什么都不显示。查下来两个原因：

**坑一**：`onChunkReceived` 的 `res.data` 在真机上是 `ArrayBuffer`，开发者工具里是字符串。
`if (typeof chunk !== 'string') return` 直接把所有分片丢了。手写了个 UTF-8 解码器，
还得处理 4 字节字符的代理对。

**坑二**：一行 SSE 可能被切在两个 chunk 之间。按单包 `split('\n')` 会丢掉半包。
改成维护跨包缓冲，只处理完整的行，残片留到下一个包。

### 3. Canvas 导出长图

`type="2d"` 的新 Canvas 不支持旧的 `setFillStyle / setFontSize`，
封装了 `setFill / setFont` 同时走两套。

高度用两遍绘制解决：第一遍给足高度把内容画一遍、记录真实结束位置，
第二遍按真实高度重设 canvas 再重绘。不然要么截断要么底部一大片空白。

## 测试

59 项断言，全部离线。做法是把 `wx` 和 `wx.request` 都 mock 掉，
再用 Proxy 模拟 canvas context：

```js
const ctx = new Proxy({
  measureText: (t) => ({ width: String(t).length * 11 }),
  createLinearGradient: () => ({ addColorStop() {} })
}, { get(o, k) { return k in o ? o[k] : (() => {}) } })
```

流式解析也能离线测：拿到 request task 后手动触发 `task._cb({ data })` 模拟分片，
不需要真实网络和 API Key。

## 几个不报错的坑

- `env()` 不带 fallback 会让整条 `calc()` 失效，固定底栏跑到屏幕顶部
- WXSS 同名类静默覆盖（`.tp-bar` 定义了两次：缩略图细线 + 固定底栏）
- tabBar 页面不能带参跳转，得走 `switchTab` + 全局中转
- `wx:for` 不写 `wx:for-item` 时默认叫 `item`，写别的名字静默渲染空白
- `rich-text` 内部节点不继承页面样式，全得内联

## 许可

衍生自 Magic Resume，Apache 2.0 + 附加非商用条款。个人使用和学习没问题，
想商用要先联系原作者。
```
